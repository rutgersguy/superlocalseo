## Operational notes and limitations

- Migration `20261015140000_qa_billing_and_archives` adds `locations.archived_at`,
  the updatable `active_locations` view and `stripe_webhook_events`.
  Foreign keys continue referencing `locations`; archiving does not cascade-delete.
  Operators can recover archived rows after checking purchased capacity, retained
  resource limits and primary-location selection. No automatic restore is promised.
  Do not drop the archive column during rollback: it would reactivate retained rows.
- Dedupe records mark successfully processed event IDs. Interrupted events can
  retry; provider side effects still require their existing idempotent/reconciliation
  behavior. This is not an exactly-once delivery guarantee across Stripe/email.
- No self-service legacy migration was added, and no Stephen account change was
  made. Paid directory credits, provider email/SMS setup and vendor scan latency
  are separate from self-service direct Google review links.
